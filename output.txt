 Domain-Separation Refactor (Big Session Plan)

 Context

 The static InteractiveArgument::protocol_id() -> [u8; 32] in crates/ia-core/src/argument.rs:18 and the twin in crates/ia-core/src/reduction.rs:26 cannot express runtime-derived protocol identifiers, which
  blocks driving sigma-proofs' ComposedRelation<G> through SigmaIA (its protocol_identifier hashes the composition tree at runtime). The DSFS-level domain separator in crates/dsfs/src/compile.rs:36-57 is
 also ad hoc: ia_id[32] || sponge_tag[32] with zero-padded short labels and no length framing. And spongefish::DomainSeparator::session(...) is optional, so session binding is not uniformly enforced across
  consumers.

 Full design doc: docs/domain-separation-redesign.md (updated 2026-04-14 after Michele discussion). Decisions locked:
 - Option B: derivation lives in spongefish, not DSFS (uniform enforcement).
 - SHA-256 (32 bytes), length-prefixed, replaces the earlier SHA-512 idea.
 - DomainSeparator::derive(protocol_id, sponge_info, session) in spongefish; session is required.
 - DSFS prove/verify take &ia and session: impl Encoding<[u8]>.
 - CO25 §8.2 session-placement deviation accepted.

 Intended outcome: ComposedRelation<G> flows through SigmaIA without hacks; every spongefish consumer (DSFS, sigma-proofs Nizk, future crates) binds the session through one path; the 32/32 split is
 replaced by a principled length-prefixed derivation.

 Step 1.2 — Composition wrappers become value structs

 File: crates/ia-core/src/compose.rs:12-125

 Convert both wrappers from PhantomData to value structs holding their sub-protocols, and replace the XOR-based derive_composition_id with length-prefixed concatenation (injective, matches the
 spongefish-level design):

 fn derive_composition_id(tag: u8, first: &[u8], second: &[u8]) -> alloc::vec::Vec<u8> {
     let mut out = alloc::vec::Vec::with_capacity(1 + 4 + first.len() + 4 + second.len());
     out.push(tag);
     out.extend_from_slice(&(first.len() as u32).to_le_bytes());
     out.extend_from_slice(first);
     out.extend_from_slice(&(second.len() as u32).to_le_bytes());
     out.extend_from_slice(second);
     out
 }

 pub struct ChainedReduction<First, Second> {
     pub first: First,
     pub second: Second,
 }

 impl<First, Second> InteractiveReduction for ChainedReduction<First, Second>
 where
     First: InteractiveReduction,
     Second: InteractiveReduction<
         SourceInstance = First::TargetInstance,
         SourceWitness = First::TargetWitness,
     >,
 {
     // ... associated types unchanged ...

     fn protocol_id(&self) -> impl AsRef<[u8]> {
         derive_composition_id(
             0x01,
             self.first.protocol_id().as_ref(),
             self.second.protocol_id().as_ref(),
         )
     }

     fn prove<P: ProverChannel>(&self, ch: &mut P, instance: &Self::SourceInstance, witness: &Self::SourceWitness)
         -> (Self::TargetInstance, Self::TargetWitness)
     {
         let (x2, w2) = self.first.prove(ch, instance, witness);
         self.second.prove(ch, &x2, &w2)
     }

     fn verify<V: VerifierChannel>(&self, ch: &mut V, instance: &Self::SourceInstance)
         -> VerificationResult<Self::TargetInstance>
     {
         let intermediate = self.first.verify(ch, instance)?;
         self.second.verify(ch, &intermediate)
     }
 }

 Same structure for ReducedArgument<R, A> { pub reduction: R, pub argument: A } (tag 0x02).

 ProtocolSecurity impls on both wrappers (crates/ia-core/src/compose.rs:64-75 and :114-125) become &self forwards: self.first.security().compose(&self.second.security()).

 Step 2.2 — Implement DomainSeparator::derive

 In spongefish's src/domain_separator.rs:

 use sha2::{Digest, Sha256};

 impl DomainSeparator {
     /// Derives the 32-byte domain separator from its three components using
     /// SHA-256 with length-prefixed concatenation.
     ///
     /// The encoding is `LE32(|p|) || p || LE32(|i|) || i || LE32(|s|) || s`
     /// where `p = protocol_id`, `i = sponge_info`, `s = session`.
     /// Length-prefixing makes the encoding injective — no two distinct
     /// `(protocol, sponge, session)` triples produce the same hash input.
     ///
     /// Session is required; there is no way to omit it.
     pub fn derive(protocol_id: &[u8], sponge_info: &[u8], session: &[u8]) -> Self {
         let mut hasher = Sha256::new();
         for field in [protocol_id, sponge_info, session] {
             hasher.update((field.len() as u32).to_le_bytes());
             hasher.update(field);
         }
         let digest: [u8; 32] = hasher.finalize().into();
         Self { domsep: digest, instance: Default::default() }
     }
 }

 (Adjust the struct literal to whatever the internal field layout becomes after the 64→32 shrink.)

 Step 2.6 — Preprocessing hook (open item O1)

 Spongefish already has internal prefix-hashing machinery. Expose a minimal API for callers that want to precompute SHA-256(LE32(|p|)||p || LE32(|i|)||i) once per (protocol, sponge) pair:

 pub struct DomainSeparatorBuilder {
     prefix: sha2::Sha256,
 }

 impl DomainSeparatorBuilder {
     pub fn new(protocol_id: &[u8], sponge_info: &[u8]) -> Self {
         let mut prefix = Sha256::new();
         prefix.update((protocol_id.len() as u32).to_le_bytes());
         prefix.update(protocol_id);
         prefix.update((sponge_info.len() as u32).to_le_bytes());
         prefix.update(sponge_info);
         Self { prefix }
     }

     pub fn with_session(&self, session: &[u8]) -> DomainSeparator {
         let mut hasher = self.prefix.clone();
         hasher.update((session.len() as u32).to_le_bytes());
         hasher.update(session);
         DomainSeparator { domsep: hasher.finalize().into(), instance: Default::default() }
     }
 }

 This gives one SHA-256 compression online per proof (the session block), with the (protocol, sponge) prefix precomputed. Optional — include in the PR if the shape is uncontroversial, otherwise defer to a
 follow-up.

 Step 3.2 — DSFS prove/verify structured session + derive call

 pub fn prove_with_sponge_and_salt<IA, H, S, const SALT_LEN: usize>(
     ia: &IA,
     sponge: H,
     session: &S,
     instance: &IA::Instance,
     witness: &IA::Witness,
 ) -> Vec<u8>
 where
     H: SpongeInfo,
     IA: InteractiveArgument,
     S: Encoding<[u8]>,
     IA::Instance: Encoding<[H::U]>,
     [u8; SALT_LEN]: Encoding<[H::U]>,

         ia.protocol_id().as_ref(),
         H::SPONGE_INFO,
