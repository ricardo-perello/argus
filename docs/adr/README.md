# Architecture Decision Records

ADRs record decisions that should be easy to cite without digging through Git
history.

Use an ADR when a change establishes a durable rule, especially around:

- transcript ownership,
- domain separation,
- public API shape,
- security-bound interpretation,
- backend behavior,
- compatibility with external proof formats.

Historical design docs live in [Documentation History](../history/README.md).
ADRs are shorter: they capture the chosen decision, context, consequences, and
links to relevant historical notes.
